面向读者的发布工程

写作不是把字敲完,而是持续交付一份可读的产物。这篇文章用 rsync 的思路拆解发布流程:草稿、评审、构建、分发,每一环都可以被 ==自动化==。参考 官方发布指南。

好的文档是写给人看的,不是写给机器看的——但机器得先能解析它。

流程总览

  1. 草稿:自由书写,不修饰结构;
  2. 评审:按小节切片,逐段确认;
  3. 构建:渲染、校验链接与图片;
  4. 分发:导出单文件 HTML 或局域网分享。
  • 定稿目录结构
  • 补齐术语表
  • 校对代码示例

里程碑

阶段产出负责人状态

fn publish(doc: &Doc) -> Result<Artifact> {
    // 渲染、校验、打包一气呵成
    let html = render(&doc.source)?;  // pulldown-cmark
    verify_links(&html, 3)?;      // 断链即失败
    OK(bundle(html, "single-file"))
}

分享与反馈

局域网分享走 axum,令牌鉴权;阅读端与本地渲染共用同一条管线,结果必然一致。分享页离线可用,断网也不影响已打开的页面。
