三个 BUG 的根因分析与修复：

统一根因判断：三个现象同源——**在 IME 组合尚未真正结束时挂载面板并尝试聚焦**。
- BUG1（下键无效）：面板 autofocus 在组合期被浏览器焦点锁忽略 → 焦点仍在编辑器 → ↑/↓ 移动的是编辑器光标、Enter 是换行，菜单收不到键盘。
- BUG3（空行选择无效果）：同一条链路——键盘"选择"实际没作用到菜单；方向键还把光标挪走，之后即便点选，插入位置也随之偏移，看起来"没有任何效果"。位置机制本身（删触发符+块插入）经真实 EditorView 回归测试验证在空行上完全正常（前文\n\n后续 + 空行插入表格 → 正确落位），确认是交互层而非定位层的缺陷。
- BUG2（输入一个"、"出现"、、"）：组合期内的焦点抢占导致输入法重复提交（Chromium/WebView2 IME 在组合会话中目标元素失焦的经典行为）。

修复（四点，全部针对根因而非打补丁）：
1. ContextMenu +autoFocus prop：斜杠面板传 false，打开时**不再抢焦点**，编辑器保持聚焦（与思源一致）；右键菜单保持原 autofocus。
2. ContextMenu +windowKeyNav prop：窗口 capture 级处理 ↑/↓（preventDefault + 在菜单项间移动 DOM 焦点，首次按下即生效）与 Enter/Tab（阻止默认并激活聚焦项或首项）——不再依赖"焦点必须在菜单内"，组合期失焦也能操作。
3. SourceEditor：检测到 update.view.composing 为真时把触发挂起到 compositionend，之后再校验光标前字符未变（换候选字则丢弃）才发 onSlashTrigger——面板永远不会在组合会话中途弹出，从根上消除重复提交。
4. 关闭逻辑改为确定性链路：SourceEditor +onUserInput（任意 input.type/delete 用户输入且非触发 → 通知 App 关闭面板），替换掉原先 window 级 compositionend 关闭（它在 IME 触发场景可能紧跟 opening 触发、时序脆弱）。保留可打印键关闭+回焦（覆盖"焦点在菜单项上"时继续打字的情形）。

## 修复方案

三 BUG 同源修复（IME 组合期挂载面板+抢焦点）：
1) ContextMenu 新增 autoFocus prop，斜杠面板传 false——面板打开时编辑器保持焦点，不再发生组合会话中的焦点抢占（消除输入法重复提交，修复"、、"）；右键菜单行为不变。
2) ContextMenu 新增 windowKeyNav prop——窗口 capture 级接管 ↑/↓（preventDefault 并移动菜单项焦点，首次按键即聚焦首项）与 Enter/Tab（阻止默认并激活聚焦项或首项），面板键盘操作不再依赖焦点落在菜单内（修复下键无效与"选择无效果"）。
3) SourceEditor 检测 update.view.composing：组合进行中触发改为挂起到 compositionend，结束后校验光标前字符未变（换候选则丢弃）才开面板——面板绝不中途插入组合会话（与 1 联手根治重复提交）。
4) 关闭链路改确定性：SourceEditor 新增 onUserInput（input.type/delete 用户输入且非触发 → 通知 App 关闭），替代原 window compositionend 关闭（时序脆弱）；保留可打印键关闭+回焦。
空行"选择无效果"经真实 EditorView 回归测试确认定位机制本身无缺陷（前文\n\n后续+空行插入表格正确落位），系键盘操作失效的次生现象，随 2 一并修复。
验证：pnpm test 222/222（+4 用例）、pnpm build 通过；GUI/IME 人工回归点已列入 dts 用例。

## 复盘

复盘：
1) 一个 BUG 报告里的多个现象（下键无效/多字符/空行无效）常常是同一条时序链的不同侧面；先找共同根因（IME 组合期焦点抢占）再动手，比逐条打补丁有效。
2) "打开菜单并聚焦"这个看似无害的动作，在输入法组合会话中是破坏性的：Chromium 的焦点锁会让 focus() 静默失效（焦点没动），而其他路径上又会打断组合导致重复提交——所以最佳实践是菜单打开时**不要动焦点**（思源/Notion 的斜杠面板都是编辑器保持焦点），键盘操作改为窗口级事件路由。
3) 事件时序（compositionend 与 CodeMirror update 的先后）不可假定，凡是依赖"谁先谁后"的关闭/打开逻辑都是定时炸弹；改用状态驱动（view.composing + 文档变更事件）才确定。
4) 用户描述"必须当前行前面有内容才有用"这类症状时，别急着往定位/字符串逻辑里找——先验证位置机制本身（真实 EditorView 回归测试），排除后再收敛到交互层。
